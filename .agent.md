## Architectural Decisions Already Made

- AR: AR.js + A-Frame (CDN, no build step for the AR page)
- Backend: Express + Socket.IO (ESM, Node 20+)
- Frontend lobby/join: plain HTML/JS (no React for prototype speed)
- Database: MongoDB Atlas (same cluster as dino-pub), DB name `scorched-earth`
- Hosting: Render (backend) + Netlify (frontend)
- Trajectory: computed server-side as array of ~60 waypoints, broadcast to all clients
- Player identity: localStorage only, no server-side sessions
- DiceBear: `https://api.dicebear.com/9.x/adventurer/svg?seed={username}`

## Do Not Change Without Discussion

- URL schema (`/venue/:venueId/table/:tableNo`) — must be stable for printed QR codes
- Socket event names once defined in Phase 1 — changing them breaks all clients
- Trajectory computation location (always server-side for authoritative hit detection)

## What to Watch For in Codex Output

- AR.js requires HTTPS in production — check that dev instructions mention ngrok or local cert
- A-Frame `<a-marker>` must wrap scene content, not be a sibling of it
- Socket.IO rooms: room name should be `gameId`, not tvId (different from dino-pub)
- Elevation angle: must be validated server-side (clamp to 5–85° to avoid degenerate trajectories)
- `socket.to(room).emit()` excludes sender; `io.to(room).emit()` includes sender — use `io.to()` for game state broadcasts so the firing player also gets the trajectory
